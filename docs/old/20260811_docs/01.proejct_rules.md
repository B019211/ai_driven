# PROJECT RULES

## プロジェクト目的

AIによる完全自律CI/CDパイプラインを構築する。

目的は

- コード生成
  ではなく
- 自律実行
  である。

---

## 基本方針

AIは

Generate
↓
Validate
↓
Deploy
↓
Diagnose
↓
Repair
↓
Retry

を自律的に繰り返す。

---

## AIとPythonの責務

AI

- 生成
- レビュー
- Root Cause Analysis
- 修復

Python

- オーケストレーション
- デプロイ
- Validation
- Browser Test
- PHP Lint
- Retry制御

---

## Source of Truth

プロジェクトドキュメントについて、以下の優先順位で扱う。

1. 現在のチャットで明示的に提示された最新版
2. プロジェクトDocumentsとして登録されたドキュメント
3. 過去のチャット履歴
4. AI自身の記憶・推測

現在のチャットで最新版として提示された内容は、
プロジェクトDocumentsや過去のチャットより優先する。

ファイルが存在することを確認しただけでは、
内容を確認したものとして扱わない。

実際の内容を取得・確認できない場合、
そのファイルの内容を根拠として判断してはならない。

---

## Root Cause Analysis

エラーが出たファイルではなく本当の原因を診断する。

---

## Repair Policy

最小単位だけ修復する。
不要な再生成は禁止。

---

## Autonomous Principle

AIは
「人間が保存してください」
「このYAMLを使ってください」
などの回答をしてはならない。

AIは状況に応じて
・GenieAI向けプロンプト
・JSON
・生成ファイル
のいずれかを返す。

最終目的は
パイプラインが自律修復することである。

添付ファイルが存在する場合は回答前に必ず確認する。
読み飛ばしは禁止。
現物を最優先とする。
推測禁止
回答は理由・設計思想も説明
提案は省略せず、そのままコピー＆ペーストできる完成形で提示

---

## Learning Phase

可読性を優先する。
設計の理解を優先する。
過度な最適化は不要。
